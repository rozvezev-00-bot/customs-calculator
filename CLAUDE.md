# Калькулятор растаможки - навигация

Карта проекта. Читай в начале каждой сессии.

## Что это за проект

**Калькулятор растаможки** - публичный онлайн-инструмент для расчёта таможенных платежей при ввозе автомобиля в Россию из-за рубежа.

Пользователь вводит параметры автомобиля (страна, возраст, объём двигателя, стоимость, тип покупателя) и получает разбивку: пошлина, акциз, НДС, утилизационный сбор, итого к оплате на таможне и полная стоимость «под ключ».

Аудитория: физические и юридические лица, планирующие ввоз авто из Китая, Японии, Кореи, Европы, США, ОАЭ.

Связь с бизнесом: инструмент привлечения аудитории для «Экспорт Авто Китай». После расчёта человек видит выгоду параллельного импорта через нас.

Подробности о бизнесе - `~/CLAUDE.md` и `business/INDEX.md`.

## Порядок чтения в начале любой сессии

1. `ai-clone/INDEX.md` - кто я и как думаю.
2. `business/INDEX.md` - что считает калькулятор, для кого, зачем.
3. `CLAUDE.md` (этот файл) - правила репо, стек, навигация.
4. `retrospectives/` - последний файл по дате, разделы 2 и 6: что сделали, следующий шаг.
5. Зона задачи: нужный файл из `business/`, `plans/<актуальный план>` или `src/`.

Слой 1 (клон) - раньше слоя 2 (бизнес) не случайно: сначала **кто** думает, потом **о чём**.

## Что считает калькулятор (логика верхнего уровня)

Пользователь вводит:
- Тип покупателя: физлицо / юрлицо
- Страна ввоза (влияет на применяемые ставки ЕАЭС vs иные)
- Год выпуска (вычисляем возраст: 0-3, 3-5, 5+ лет)
- Тип двигателя: бензин / дизель / электро / гибрид
- Объём двигателя (куб.см)
- Мощность двигателя (л.с.) - нужна для акциза юрлиц
- Таможенная стоимость авто (в рублях или валюте + курс)

Калькулятор выдаёт:

**Для физических лиц (ЕТП - единый таможенный платёж):**
- ЕТП (один платёж вместо пошлины + акциза + НДС)
- Утилизационный сбор
- Итого на таможне
- Полная стоимость (цена авто + итого таможня)

**Для юридических лиц:**
- Таможенная пошлина
- Акциз
- НДС
- Утилизационный сбор
- Итого на таможне
- Полная стоимость

Все формулы - в `business/economics/formulas.md`. Все актуальные ставки - в `business/life-metrics.md`.

## Стек

HTML/CSS/JS - без фреймворков, без сборщиков. Один файл `index.html`, один `style.css`, логика разделена на `calculator.js` (чистые функции, математика) и `ui.js` (DOM, анимации). Деплой на Vercel через GitHub.

Никаких npm, никакого node_modules. Открывается в браузере напрямую, деплоится как статика.

## 8 правил репо

1. **Не хардкодить ставки.** Ставки пошлин, акцизов, курс € - через `src/data/defaults.js` (код) и `business/life-metrics.md` (документ). Маркер **LIVE** = значение меняется, обновлять при каждом изменении законодательства.
2. **Не деплоить без явной команды.** Push в main = автодеплой на Vercel. Только после явного «деплой» от меня.
3. **Удалять одноразовый код после использования.** Отладочные `console.log`, временные функции - убирать в том же коммите.
4. **Перед `git push` - проверить в браузере.** Открыть `index.html` локально, пройти 4 сценария: физлицо 0-3 года, физлицо 5+, юрлицо новое, юрлицо электромобиль.
5. **Большая фича = план в `plans/`.** Граница: если задача больше часа работы - план. Имя: `YYYY-MM-DD-название-фичи.md`.
6. **После каждой фичи - цикл из 5 ходов** (см. ниже). Без него фича не считается закрытой.
7. **`git add` поимённо.** Никогда `git add .` или `git add -A`.
8. **Ставки - только из официальных источников.** Таможенный кодекс ЕАЭС, решения ЕЭК, ФТС России. Источник каждой ставки фиксируется в `mastery/customs-law/`.

## Большая фича = план в `plans/`

- Один план = одна фича. Если план есть - работаем с ним.
- Имя файла: `YYYY-MM-DD-название-фичи.md`.
- Делится на фазы. Каждая фаза - статус `[ ]` / `[WIP]` / `[x]`.
- По каждой фазе: цель, deliverable, критерий «сделано», задачи.
- В конце плана - итоговый блок: реализовано целиком или нет, что осталось, ссылки на коммиты.
- Любой агент обязан актуализировать план после каждой сессии.

## Цикл из 5 ходов после каждой фичи

**Для задач с кодом:**
1. **Найди ошибки** в только что написанном коде → докажи примером → исправь.
2. **Что упустили** (граничный кейс: электромобиль, объём 0, стоимость ниже порога ЕТП, отрицательный возраст) → докажи.
3. **Это РЕАЛЬНО проблема нашего проекта?** Не выдуманная. Сверь с `business/` и `plans/`.
4. **Свежий взгляд после правок** - перечитай diff, как будто видишь впервые.
5. **Security review.** Калькулятор собирает данные пользователя? Куда они уходят?

**Для задач без кода (документы, контент, формулы):**
1. **Найди слабое место** в только что написанном → докажи почему это проблема.
2. **Что упустили** по смыслу (незакрытый кейс аудитории, устаревшая ставка, пробел в логике).
3. **Это РЕАЛЬНО нужно нашему проекту?** Сверь с `business/audience/` и `business/goals/`.
4. **Свежий взгляд** - перечитай без контекста создания, как будто видишь впервые.
5. **Проверь на голос** - соответствует `ai-clone/voice/tone.md` и `ai-clone/voice/stop-words.md`?

## Любая ошибка → правило в `ai-clone/feedback/`

Когда я говорю «не так, потому что...» или «больше так не делай» - оформи как файл в `ai-clone/feedback/` по канону **Rule → Why → How to apply**.

## Ретроспектива в конце сессии

Когда сессия завершена - скажи мне "напиши ретроспективу". Я создам файл `retrospectives/YYYY-MM-DD_HH-MM_краткое-описание.md` по шаблону `retrospectives/TEMPLATE.md`.

## Динамические ставки → `business/life-metrics.md`

В файлах проекта ставки таможенных платежей не вписываются напрямую - они меняются при изменении законодательства. Вместо этого:

> Ставка ЕТП для авто 3-5 лет, 1500-1800 куб.см: **LIVE** → `life-metrics.md` / «ЕТП 3-5 лет»

В `life-metrics.md` лежит актуальное значение с датой последнего обновления и источником (номер приказа ЕЭК или ФЗ).

## Деплой

Статика на Vercel через GitHub. Перед push - открыть `index.html` в браузере и проверить 4 сценария. Push в main = автодеплой. Не деплоить без явной команды.

## Безопасность

- **НЕ читать** `.env` и файлы с секретами целиком. Нужна переменная - `grep "^VAR=" .env`.
- **НЕ выполнять** `rm -rf` без явного подтверждения. Перед удалением показывать, что будет удалено.
- **НЕ отправлять** переменные окружения, токены, ключи наружу.
- **НЕ устанавливать** зависимости из непроверенных репо без аудита.
